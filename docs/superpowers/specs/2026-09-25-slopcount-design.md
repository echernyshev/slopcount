## 1. Концепция

`slopcount` — шуточная command-line утилита, пародирующая классический
`sloccount` Дэвида Уилера. Она сканирует проект, детектирует «нейрослоп»
(LLM-сгенерированный контент) и оценивает, сколько ресурсов потребуется,
чтобы этот слоп осознать и понять.

**Инверсия-изюминка:** sloccount оценивает, сколько стоило *написать* код
(Basic COCOMO); slopcount оценивает, сколько стоит *понять* слоп. В этом
суть шутки про эру AI: генерация бесплатна, осознание — дорого.

**Душа утилиты — сатира с ядром правды:**

- детекция и когнитивные метрики считаются *честно* (регекс-эвристики,
  когнитивная сложность Кэмпбелла, скорость чтения по Brysbaert);
- подача — пародия на формат sloccount с шуточными единицами
  (человеко-месяцы осознания, терапия, GPU-часы, чашки кофе);
- каждая улика объяснима: можно показать, *почему* строка считается слопом.

### Название и единицы

| sloccount | slopcount |
|---|---|
| SLOC — Source Lines Of Code | **SLOP** — Suspicious Lines Of Prose |
| Basic COCOMO: стоимость разработки | **SLOCOMO**: стоимость осознания |
| Total Estimated Cost to Develop | **Total Estimated Cost to Comprehend** |
| Estimated Average Number of Developers | **Estimated Average Number of Therapists** |

### Не-цели (out of scope v1)

- Ватермарки, Binoculars, Fast-DetectGPT (дорогие/непрактичные детекторы)
- Обучение классификаторов кода
- Онлайн-API и внешние сервисы (всё работает офлайн)
- Локализация интерфейса (каталоги фраз — EN+RU, вывод — EN с русскими вердиктами)

## 2. Исследовательский фундамент

### 2.1. Что делает оригинальный sloccount

- Считает **физический SLOC** (строки без пустых и комментариев) по языкам,
  таблица отсортирована по доминирующему языку.
- Basic COCOMO: `Person-Months = 2.4 × (KSLOC ** 1.05)`;
  расписание: `Months = 2.5 × (person-months ** 0.38)`;
  среднее число разработчиков = Effort / Schedule;
  стоимость = person-months × $4,690.50 × overhead 2.4.
- Реализован как Perl-скрипт-дирижёр + маленькие C-счётчики (`c_count` и т.п.),
  зависимостей — только стандартный Perl и libc.

### 2.2. Детекция LLM-текста: что практически применимо офлайн

| Подход | Вывод исследования |
|---|---|
| Регекс-эвристики (фразы-маркеры) | Мгновенно, офлайн, объяснимо — ядро инструмента |
| Маркеры окружения (`CLAUDE.md`, `.claude/`, `Co-Authored-By: Claude`) | Почти улика: констатация присутствия агентов |
| Перплексия + burstiness (GPTZero-стиль, GPT-2 локально) | Работает офлайн, ~300–500 МБ модели; добавляет точность по «гладкой» прозе |
| Стилометрия кода | Научно ненадёжна по отдельности, но в сумме даёт сигнал с малыми весами |
| Объём документации | Новый вклад нашей сессии: md-бантон — самостоятельный симптом слопа |
| DetectGPT/Binoculars/ватермарки | Отвергнуты: оверкилл для шуточной тулзы |

Ключевой факт: AI-**проза** (комментарии, докстринги, README, коммит-месседжи)
детектится надёжно, AI-**код** по стилю — шумно. Поэтому детекция строится
вокруг прозы, а стиль кода даёт лишь малые веса.

## 3. Архитектура: «скрипт-дирижёр»

Оммаж sloccount: один CLI-движок гоняет проект через конвейер независимых
детекторов; каждый детектор возвращает **улики** (evidence); агрегатор
считает баллы; SLOCOMO конвертирует в человеко-месяцы и шутливые ресурсы;
рендереры выводят результат.

```
файлы ──→ scanner ──→ [phrase]      ──┐
git     ─→ history ──→ [env_markers]──┤
md      ─→ docs ─────→ [code_style] ──┼──→ evidence ──→ SLOCOMO ──→ render
                              [perplexity]  агрегатор   (SLOP →     (text /
                                            (веса,      когнитивный  json /
                                            категории)  вес → PM)    csv)
```

Принципы:

- **Улики объяснимы**: `{файл, строка, категория, вес, объяснение}` — база
  для `--details` и юмора («вот ваша улика, вот её вес»).
- **Правила вынесены в TOML** — комьюнити может расширять каталоги фраз.
- **Ноль зависимостей в ядре** (stdlib, `tomllib`), опциональные extras.
- **Пять категорий не смешиваются**: `prose`, `docs`, `style`, `agency`,
  `history` — отдельные строки отчёта и отдельные колонки в JSON.

## 4. Детекторы

### 4.1. `phrase_detector` — классические фразы LLM (категория `prose`)

Регекс-правила из TOML-каталогов (`phrases_en.toml`, `phrases_ru.toml`;
юзер расширяет через `--rules`). Вес по «токсичности»:

- вес **5** (железная улика): `Great question!`, `Certainly!`,
  `As an AI language model`, «Отличный вопрос!», «Конечно!»
- вес **3**: `It's not X, it's Y` (паттерн), `Here's a comprehensive ...`,
  «Давайте рассмотрим подробнее»
- вес **2**: `Let's delve into`, `It's important to note`, `In conclusion`,
  `dive deep`, `seamlessly`, `robust solution`, «Важно отметить»

Ареал: комментарии, докстринги, md-файлы, README, коммит-месседжи.

### 4.2. `docs_bloat_detector` — документационный бантон (категория `docs`)

- **Spec-to-Code Ratio**: байт `*.md` на KLOC кода; тревога при >100 КБ/КЛОК
- Количество и средний размер md-файлов
- «Спеки-гиганты»: md-файлы длиннее 500 строк
- Эмодзи-заголовки (`## 🚀 Quick Start`) — вес по плотности

### 4.3. `code_style_detector` — стилометрия кода (категория `style`)

Малые веса (1–2), по отдельности шумно, в сумме — сигнал:

- докстринг длиннее тела функции
- тривиальная функция с докстрингом («Adds two numbers and returns the result»)
- плотность catch-all (`except Exception` / `catch (e)`) выше порога
- идеальные Google-style докстринги (Args/Returns) в каждой функции файла
- эмодзи в комментариях кода (`🤖 ✨ 🎉`)
- монотонная длина строк комментариев (низкая дисперсия = машина)

### 4.4. `env_marker_detector` — индекс агентской оккупации (категория `agency`)

Маркеры присутствия AI-тулз: `.claude/`, `CLAUDE.md`, `AGENTS.md`,
`.cursor/`, `.aider*`, `.github/copilot-instructions.md`, заголовки
«Generated by Claude/ChatGPT/Copilot». Это отдельная корзина баллов —
не обвинение, а констатация: «в проекте живут агенты». Отображается
отдельной строкой отчёта; в Slop Ratio и шкалу вердиктов **не входит**.

### 4.5. `git_history_detector` — археология слопа (категория `history`, флаг `--history`)

- коммит-месседжи: `Co-Authored-By: Claude`, `Generated with Claude Code`,
  `aider:`, эмодзи в сообщениях
- **«Машинная скорость»**: >2000 строк одним коммитом
- **«Коммиты в 4 утра»**: подозрительная ночная активность (машина не спит)
- идеальный conventional-commits у 100% коммитов (человек ленится)

### 4.6. `perplexity_detector` — гладкость прозы (флаг `--perplexity`)

Локальная LM (GPT-2 или smolLM, ~300–500 МБ, ставится через extras
`[perplexity]`, модель скачивается `python -m slopcount.download-model`).
По предложениям: низкая средняя перплексия + низкий burstiness → баллы.
Работает по прозе (комментарии, докстринги, md). Улики попадают
в категорию `prose`.

### Агрегация

Каждая улика несёт вес; файл получает **slop density** (улико-баллы на
KLOC). Md-файл считается **заражённым**, если плотность улико-баллов
превышает 0.1 балла на строку.

## 5. SLOCOMO — модель стоимости осознания

### Шаг 1. SLOP — Suspicious Lines of Prose

- **SLOP** = строки с ≥1 уликой (прямые попадания; включая строки
  коммит-месседжей при `--history`) + строки заражённых
  md-файлов × коэффициент уверенности **0.8**
- **SLOC** считаем честно, как sloccount: физические строки кода без
  пустых и комментариев (регексы синтаксиса комментариев по топ-языкам:
  py, js/ts, go, rs, c/h/cpp, java, rb, sh, php, cs, swift, kt, scala;
  md в SLOC не входит — это проза)
- **Slop Ratio** = SLOP / SLOC — главный показатель «утопленности»
  (может превысить 100% — это предусмотрено шкалой вердиктов)

### Шаг 2. Когнитивный вес (честные модели)

| Компонент | Формула | Источник |
|---|---|---|
| Чтение слоп-прозы | `слова / 238 wpm × 2.3` | Brysbaert 2019 + «коэффициент перечитывания от недоверия» (шутка, помечена в выводе) |
| Слоп-код | `Σ Cognitive Complexity × 0.5 мин` | Campbell 2018, 1 балл ≈ полминуты осознания |
| Ментальное усилие | Halstead Effort `E = (V × D) / 18` | Halstead 1977 |

Cognitive complexity считается честно через tree-sitter при наличии extras
`[treesitter]`, иначе — индентационная аппроксимация с пометкой
«approximate» в выводе.

### Шаг 3. SLOCOMO — пародийная надстройка (структура COCOMO 1-в-1)

```
Awareness Effort, Person-Months = 2.4 × (KSLOP ** 1.05)
Schedule of Despair, Months     = 2.5 × (person-months ** 0.38)
Estimated Average Number of Therapists = Effort / Schedule
```

### Шаг 4. Конвертация в шутливые ресурсы

| Метрика | Формула | Дефолты (настраиваются) |
|---|---|---|
| **Cost to Comprehend** | person-months × personcost × overhead | $4,690.50 × 2.4 (как у sloccount) |
| **Context Windows Consumed** | slop-токены / 200,000 и / 1,000,000 | окна Claude |
| **GPU-hours of Regret** | slop-токены / 100 tok/s / 3600 | «сгенерировать заново» |
| **Coffee Required** | человеко-часы / 4 | $4 за чашку (`--coffee-price`) |
| **Therapy Sessions** | person-months × 2 сессии/мес × $150 | отключается `--no-therapy` |

Логика честности: сначала честный счёт (SLOP, сложность, слова), потом
честная формула с шуточными константами, потом шуточные единицы. Каждый
шаг можно проверить.

### 6.2. Шкала вердиктов (по Slop Ratio)

| % | Вердикт |
|---|---|
| 0–10% | «Почти человек. Подозрительно чисто. Где вы прячете слоп?» |
| 10–25% | «Лёгкое нейро-облако: слоп уже завезли, но пока моет посуду» |
| 25–50% | «Слоп прочно прописался. Документации больше, чем смысла» |
| 50–75% | «Репозиторий на самообслуживании LLM. Люди здесь по выходным» |
| 75–100% | «Агентская оккупация. Сопротивление бесполезно» |
| 100%+ | «Вы запустили slopcount внутри слопа. Рекурсия» |

### 6.3. CLI

```
slopcount [paths...]              # по умолчанию — текущая директория
  --details                       # пофайловый список улик: file:line [детектор] фраза → +вес
  --json / --csv                  # машиночитаемо для CI
  --history [N]                   # археология git (последние N=500 коммитов)
  --perplexity                    # гладкость прозы через локальную LM
  --rules my.toml                 # добавить свои правила
  --personcost FLOAT              # $/person-month (дефолт 4690.50, как у sloccount)
  --overhead FLOAT                # дефолт 2.4 (как у sloccount)
  --coffee-price FLOAT            # $/чашка (дефолт 4.0)
  --no-therapy                    # убрать метрики терапии (для смирившихся)
  --fail-above PCT                # exit 1, если slop ratio выше порога — CI-режим
  --verdict-only                  # только строка вердикта (для скриптов)
  --wide                          # знакомый флаг sloccount для узнаваемости
```

`--fail-above 40 --json` делает утилиту юзабельной в CI — шутка, которую
можно поставить в пайплайн.

### Ключевые технические решения

- **Интерфейс детектора**: класс с `detect(context) -> list[Evidence]`,
  реестр по категориям; детектор декларирует ареал (файлы / проза / git).
- **Ноль зависимостей в ядре**: stdlib + `tomllib`; правила в TOML.
  Опциональные extras: `[perplexity]` → transformers/torch;
  `[treesitter]` → точный AST-разбор.
- **Python 3.11+**, установка `pipx install slopcount` (PyPI).
- Коммит-месседжи и докстринги самого slopcount пишутся так, чтобы
  сам инструмент показывал на себе ~0% слопа (заявление для README).

## 8. Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Бинарный/нечитаемый файл | молча пропустить, посчитать в сводке «skipped» |
| Не git-репозиторий при `--history` | warn в stderr, продолжить без истории |
| `--perplexity` без модели | подсказка скачать `python -m slopcount.download-model`, exit 2 |
| `--perplexity` без extras | подсказка `pipx install slopcount[perplexity]`, exit 2 |
| Огромные репо | потоковая обработка пофайлово, прогресс на stderr при tty |
| **Exit-коды** | `0` — ок; `1` — сработал `--fail-above` (CI); `2` — ошибка |

---

## 9. Тестирование

- **Fixtures-библиотека слопа**: файлы с «Great question!», гигантские md,
  defensive try/except — эталоны для юнит-тестов детекторов.
- **Контроль чистоты**: «человеческий» fixture (например, фрагмент
  linux kernel) должен давать slop ratio < 10% — защита от детектора-параноика.
- **Golden-file тесты** текстового рендерера; детерминированные тесты
  формул SLOCOMO.
- **Интеграционные тесты CLI** (прогон на fixtures, проверка exit-кодов).
- **Производительность**: 10K файлов за секунды без LM (цель, проверяется
  на большом fixture).

## 10. Порядок реализации (для плана)

1. **MVP-скелет**: scanner + честный SLOC + phrase_detector + text render
   + вердикты — утилита уже смешная и полезная.
2. **Полнота детекции**: docs_bloat + code_style + env_markers + git_history.
3. **SLOCOMO целиком**: cognitive complexity (аппроксимация), Halstead,
   шутливые конвертации, `--details`.
4. **CI-режим**: `--json`, `--csv`, `--fail-above`, `--verdict-only`.
5. **Опциональная мощь**: extras `[perplexity]` и `[treesitter]`.
6. **Полировка**: README с философией, PyPI-упаковка.
