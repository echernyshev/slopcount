# MD/SLOC: метрика недетерминированного текста и вердикт на её основе

Дата: 2026-09-26
Статус: согласован (brainstorming), ожидает плана реализации

## Мотивация

Slop Ratio (SLOP/SLOC) измеряет долю **детектированного** слопа — того, что
подтверждено уликами. Но детекция консервативна: самоскан slopcount даёт
2.4% (вердикт HUMAN), хотя в репо 4748 строк markdown на 2426 SLOC.
Объём недетерминированного текста — самостоятельный сигнал: он не зависит
от полноты каталогов фраз и видит то, что детекция пропускает.

Новая метрика **MD/SLOC** = строки markdown / строки кода. Вердикт и порог
`--fail-above` переводятся на неё. Дополнительно вводится информационная
метрика **comment_sloc_ratio** (комментарии/код), подсвечивающая баланс
прозы внутри кода — на вердикт она не влияет.

## Принятые решения

1. **Единицы**: md-строки / SLOC, доля (не проценты). Честный объём
   недетерминированного текста относительно кода.
2. **Числитель MD/SLOC**: только `.md`/`.markdown` (физические строки).
   `.rst` **исключён** — измерение показало, что rst — классическая
   Sphinx-эпоха человеческих доков (flask: 14648 rst-строк; с rst его
   ratio 1.44 → RECURSION — абсурд; без rst — 0.015 → HUMAN).
   Детекция `docs_bloat` на rst остаётся как была.
3. **Вердикт**: полная замена базиса с `slop_ratio` на `md_sloc_ratio`.
   Тексты и коды вердиктов не меняются, меняются пороги (шкала B,
   откалиброванная — ниже). Slop Ratio остаётся в отчёте как метрика.
4. **`--fail-above`**: переводится на `md_sloc_ratio` (доля).
   Breaking: значения меняют смысл (были проценты slop_ratio).
5. **comment_sloc_ratio**: информационная метрика в отчёте и JSON,
   без влияния на вердикт и гейты. Имена без сокращений.
6. **CSV не меняется**: это дамп улик, метрик он не несёт.

## Калибровка порогов

### Исследования

Норм на внешнюю документацию не существует: ISO/IEC/IEEE 26514 и
NASA-STD-2100-91 сознательно не фиксируют отношений «доки/код».
Единственный количественный якорь — comment density (внутренние доки):
He 2019 (150 проектов, среднее ~20%), гайдлайны 10–30%,
«well-commented» 30–60%. Человекописанный текст о коде — до ~30% кода.

### Замеры (методологией инструмента: scanner + count_sloc + extract_comments)

Эталонные проекты (md-only / с комментариями):

| проект | md/SLOC | comment/SLOC | (md+com)/SLOC |
|---|---:|---:|---:|
| django | 0.0005 | 0.196 | 0.196 |
| cpython | 0.005 | 0.318 | 0.323 |
| flask | 0.015 | 0.443 | 0.458 |
| requests | 0.34 | 0.348 | 0.687 |

Локальная выборка 63 репо (md-only, все чисто .md): большие upstream
(claude-code, sd40, spring-ai-alibaba) — 0.001–0.03; проекты с честными
доками (assistant-ui, WoeUSB-ng, yandex-tracker-proxy) — 0.09–0.22;
рабочие репо с агентскими доками — 0.4–0.5; агентская эра (sdd-example,
calculator, naumen-vibes, game-snake, dev-smrm-news) — 1.06–107;
slopcount — 1.96.

Почему вердикт не на (md+комментарии): комментарии — человеческая норма
(flask 0.44 = исследовательская норма well-commented), их включение
размывает границу человек/агент (flask 0.46 и metactl 0.79 почти
сливаются с ndm 1.12). md разделяет резко: человек ≤ 0.34, агенты ≥ 1.0.

### Шкала

| Вердикт | Порог md_sloc_ratio | Якорь |
|---|---|---|
| HUMAN | < 0.05 | все классические эталоны < 0.03 |
| NEURO_CLOUD | < 0.35 | потолок человеческого README: requests 0.34 |
| ESTABLISHED_SLOP | < 0.50 | текст — половина кода |
| AGENT_SELF_SERVICE | < 0.75 | три четверти |
| AGENT_OCCUPATION | < 1.00 | почти паритет |
| RECURSION | >= 1.00 | текста не меньше, чем кода |

Прогресс-бар: `progress_bar(md_sloc_ratio * 100)` — заполняется до
паритета, дальше полный (как сейчас с ratio > 100%).

## Изменения по модулям

### `app.py`

В цикле скана:

- markdown-файлы с суффиксом `.md`/`.markdown`: счётчик `md_files`,
  физические строки `md_lines` (формула docs_bloat: `len(lines)` минус
  хвостовой пустой элемент). Бинарные/нечитаемые → skip, не считаются.
- код-файлы: комментарии считаются тем же проходом, что и SLOC —
  `extract_comments` уже вызывается в `count_sloc`; добавляем
  `count_sloc_and_comments(text, language) -> tuple[int, int]`
  (один проход экстракции), `count_sloc` остаётся тонкой обёрткой
  (обратная совместимость тестов). comment_lines = сумма
  `len(block.lines)` по блокам (пустые строки внутри блоков считаются —
  консистентно с подсчётом md-строк и инвариантом экстрактора).

### `evidence.py`

`Report`: новые поля `md_files: int = 0`, `md_lines: int = 0`,
`md_sloc_ratio: float = 0.0`, `comment_lines: int = 0`,
`comment_sloc_ratio: float = 0.0` — доли, не проценты.

`aggregate(..., md_files=0, md_lines=0, comment_lines=0)`:
`md_sloc_ratio = md_lines / sloc`; `comment_sloc_ratio =
comment_lines / sloc`; при `sloc == 0` — `inf` при ненулевом числителе,
иначе `0.0` (симметрично существующему `slop_ratio`).

### `verdicts.py`

`verdict_for(md_sloc_ratio: float)`: RECURSION при `>= 1.0`, далее шкала
выше. Тексты Verdict не меняются.

### `render/text.py`

После строки Slop Ratio две новые строки (значения — доли, 3 знака):

```
Документация на код (MD/SLOC)          = 1.957 (md: 9 файлов, 4748 строк)
Комментарии к коду (comment/SLOC)      = 0.129
```

`render_verdict`: `verdict_for(report.md_sloc_ratio)`.

### `render/json_out.py`

Новые ключи верхнего уровня: `md_files`, `md_lines`, `md_sloc_ratio`,
`comment_lines`, `comment_sloc_ratio` (округление 4 знака; `inf` →
`null`, как у `slop_ratio`). В `verdict` ключ `ratio` переименован в
`md_sloc_ratio` — честное имя, breaking (документируем).

### `cli.py`

`--fail-above` сравнивает `report.md_sloc_ratio` (доля): пример
`--fail-above 0.5` — «падай, если текста больше половины кода».
Help-текст обновить.

### i18n

Новые msgid: строка MD/SLOC (с plural-счётчиком файлов), строка
comment/SLOC. Help `--fail-above` НЕ локализуется: help-строки typer
статичны (решение спеки typer-миграции), msgid не нужен. Тексты
вердиктов не трогаем.
`.po` правится → обязательно `msgfmt` (drift guard побайтово).

## Крайние случаи

| Случай | Поведение |
|---|---|
| docs-only репо (sloc=0, md>0) | `inf` → RECURSION («только текст») |
| пустое репо (sloc=0, md=0) | 0.0 → HUMAN (как slop_ratio сейчас) |
| `.rst` | не в числителе; детекция docs_bloat не меняется |
| md в .gitignore / SKIP_DIRS | не считается |
| языки без экстрактора комментариев | comment_lines = 0, SLOC считает все непустые (существующее приближение) |
| Marp/заметки-репо (md = исходник) | честный RECURSION; слепая зона, документируем |
| малые проекты | отношение шумно на малых N (3 md / 17 sloc = 0.18); документируем |
